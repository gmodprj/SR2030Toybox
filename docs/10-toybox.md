# 10. ToyBox — 게임 안 모드 설정 창

조사 기준: Steam appid `2093410`, build `21347933`(게임 12.1.1360), Windows 11(`dxgi.dll` 10.0.26100), 2026-10-06 ~ 10-07.

표기: **[확인]** 게임 안에서 직접 봤다 · **[추정]** 정황으로 판단했고 게임에서 보지 않았다.

## 무엇인가

게임 화면 위에 뜨는 모드 설정 창이다. 단추와 설정이 게임의 그 칸에 직접 쓰거나, 게임이 스스로도 부르는 게임의 함수를 부른다 — 게임의 내장 치트([07](07-cheats.md))는 쓰지 않는다.
요구는 셋이다(2026-10-06 · 10-09, 사용자):

1. 모드의 모든 기능은 **게임 안의 설정 창**에서 설정한다. 설정 파일을 고쳐 다시 빌드하지 않는다.
2. 설정한 내용은 **플레이어가 지금 플레이 중인 국가에만** 적용된다.
3. 모드의 모든 기능은 **게임의 내장 치트와 완전히 별도로 동작한다**(2026-10-09).

지금은 3단계까지 끝났다(2026-10-11).

- **1단계**: 창과, 게임이 스스로 플레이어에게만 적용하는 내장 치트 16개(글쇠로 넣었다).
- **2단계**: ToyBox 가 게임의 상태(진행 중인지, 플레이어가 어느 나라인지, 이번 판에 어떤 나라가 있는지)를 읽고, 치트를 게임의 명령 처리
  함수에 **직접** 넘기고, 나라를 골라 쓰는 치트 9개를 더했다. 게임의 안쪽은 [11](11-game-internals.md)에 적었다.
- **3단계**(2026-10-09 ~ 10-11): 요구 3 에 따라 모든 기능을 묶음별로 내장 치트에서 떼어 냈다([설계](superpowers/specs/2026-10-09-toybox-stage3-1-design.md)에 묶음의 표가 있고,
  묶음마다 한 일은 아래 "다음 단계"의 표에 있다). 주소와 값의 자리를 치트 문자열이 아니라 치트와 무관한 코드의 서명으로 찾고([11](11-game-internals.md)),
  게임의 그 칸에 직접 쓰거나 게임 자신의 함수를 부른다(부르는 함수는 열하나 — 저장소의 `CLAUDE.md` · `native/srtoybox/game.h`).
  옮기면서 세분화를 더했다 — 연구의 목록, 부대 설계도 목록과 부대 생성, 부대의 경험 · 사기 · 효율 · 보급(고른 부대 / 내 부대 전부), `배율` 탭.
  **"인구 +100만"은 자정을 넘겨도 남는다**(내장 치트는 첫 자정에 되돌아갔다 — 인구의 풀 칸에도 쓴다. 사용자가 플레이하는 판에서 유지되는 것을 봤다 [확인: 게임 — 사용자, 2026-10-10]).

내장 치트로 도는 기능은 **없다**(2026-10-11). 그 실행 경로의 코드도 지웠다 — **글쇠 방식과 직접 실행은 없다.**
ToyBox 는 게임에 글쇠를 넣지 않고, 치트 명령 처리 함수를 부르지 않고, 실행 중에 치트 문자열로 주소를 찾지 않고, 치트 허용 비트를 읽지도 켜지도 않는다.
게임 상태를 읽을 수 없으면(`SRTOYBOX_READ=0` 포함) 모든 단추가 꺼진다. **이 문서의 아래쪽에 남은 "글쇠 방식" · "직접 실행" · `SRTOYBOX_DIRECT` 의 설명과
그 확인(H 번호 등)은 옛 단계의 기록이다** — 지금의 DLL 에는 해당하지 않는다.

게임이 업데이트되어 ToyBox 가 게임을 읽지 못하게 되면 그 기능의 단추가 꺼진다(찾지 못한 묶음만 — 아래 "한계"). 싱글플레이 전용이고 Workshop 으로는 배포할 수 없다
(DLL 은 게임의 파일 로더를 거치지 않는다 — [02](02-modding-system.md)).

## 설치와 제거

```
uv run srkit hook-build              # 불러오기가 든 한글화 훅 DLL
uv run srkit build                   # 한글화 모드에 새 훅 DLL 을 넣는다
uv run srkit deploy korean --apply   # 갱신: WTSAPI32.dll 한 개
uv run srkit toybox-build            # build/toybox/srtoybox.dll
uv run srkit deploy toybox --apply   # 추가: srtoybox.dll 한 개
uv run srkit undeploy toybox --apply # ToyBox 만 뺀다
```

- **한글화 모드가 설치되어 있어야 동작한다.** 게임 폴더의 `WTSAPI32.dll`(한글화의 훅)이 옆에 있는 `srtoybox.dll` 을 불러온다. 게임 언어가
  한국어가 아니어도 불러오기는 된다 [추정: 불러오기는 언어를 보지 않는다].
- ToyBox 를 빼도 `WTSAPI32.dll` 은 한글화 모드의 파일로 남는다. `srtoybox.dll` 이 없으면 아무 일도 하지 않는다 **[확인: G8]**.
- 게임이 실행 중이면 `deploy` · `undeploy` 는 거부된다.

## 쓰는 법

- **`Ctrl+Shift+T`** 로 창을 열고 닫는다 **[확인]**. 게임이 쓰지 않는 조합이다(`INI\hotkeys.csv`).
- **창 맨 위의 상태 줄**이 ToyBox 가 게임을 어떻게 보고 있는지 알려 준다. 탭의 내용을 아래로 내려도 이 줄은 남아 있다(창은 구르지 않고
  탭의 내용만 구른다) **[확인: H17]**:
  - `플레이 중: 독일 (1499)` — 게임을 진행 중이다. 괄호 안은 지역 번호 **[확인: H2 · H16(나갔다 다시 들어간 판) · H18(캠페인)]**.
  - `게임을 진행 중이 아닙니다 — 단추가 꺼져 있습니다` — 메뉴나 로비다. 단추가 흐려지고 눌러도 아무 일도 없다 **[확인: H1 · H10 · H16]**.
  - `멀티플레이에서는 동작하지 않습니다` [추정: 멀티플레이는 띄워 보지 않았다. 자동 테스트는 가짜 게임으로 본다].
  - `게임 상태를 읽을 수 없습니다 — 단추가 꺼져 있습니다` — 게임이 바뀌어 주소를 찾지 못했거나 `SRTOYBOX_READ=0` 으로 띄웠다. 모든 단추가 꺼진다
    [확인: 코드 · 자동 테스트는 로그 줄만 본다. 1단계의 글쇠 방식은 지웠다 — 그때의 확인은 H13].
  - 게임의 함수를 부르다 예외가 나면 이 자리에 빨간 글 "<하던 일> 중 오류가 났습니다. 저장하지 말고 게임을 다시 시작하십시오."가 뜬다("한계").
    예: 연구의 단추가 부르는 "효과를 다시 셈"이 죽었을 때는 "효과를 다시 셈하는 중 오류가 났습니다. …"다.
  - **최소 유지가 켜져 있으면 뒤에 붙는다**: 게임 안에서는 `· 유지 중: 국고, 석유`(넷을 넘으면 `국고 외 5개`) **[확인: VD-3 · VD-4 · VE-3]**,
    게임 밖에서는 `· 유지 2개 켜짐(게임에 들어가면 적용)` **[확인: VD-9 · VD-11]**. 쉬는 까닭은 그 밖에 `멀티플레이에서는 쉽니다` ·
    `게임을 읽을 수 없어 쉽니다` · `값을 쓸 수 없어 쉽니다` · `값을 읽을 수 없어 쉽니다` 가 있다 [확인: 자동 테스트 — 게임에서는 보지 않았다].
- 탭: 돈 / 물자 / 배율 / 사회 / 연구 / 인구·여론 / 외교·영토 / 부대 / 화면·진행 / 설정. 단추를 누르면 그 기능이 실행된다.
- 숫자가 필요한 기능은 왼쪽 입력란에 값을 넣고 단추를 누른다. 입력란을 누르면 전체가 선택되므로 바로 치면 된다. 넣은 값은 저장된다 **[확인: G3 · G7]**.
- "즉시 승리"는 한 번 누르면 단추의 글이 "즉시 승리 — 한 번 더 누르면 실행합니다"로 바뀌고, 한 번 더 눌러야 실행된다 [추정: 게임에서 눌러 보지 않았다].
- **단추를 누르면 바로 실행된다.** ToyBox 가 게임의 메모리에 직접 쓰거나 게임이 스스로도 부르는 함수를 부른다. 게임의 설정 창은 뜨지 않는다
  **[확인: H3(일시 정지) · H15(시간이 "매우 느림"으로 흐르는 중, 두 번) — 그때는 내장 치트를 넘겼다. 지금의 쓰기는 VB · W · R 의 확인]**. 더 빠른 속도와 날짜가 넘어가는 순간에는 눌러 보지 않았다.
  **값은 바로 바뀌지만 열려 있던 게임 패널의 숫자는 스스로 바뀌지 않는다** — 일시 정지 중에도, 시간이 흐르는 중에도 그랬다. 그 패널 안을
  누르거나 패널을 다시 열면 바뀐다 **[확인: H3 · H15]**. 창 아래쪽에 그 안내가 떠 있다.
- **돈 탭**은 내장 치트를 거치지 않는다(3단계 1 (나)). 첫 줄에 지금의 국고가 보이고(`국고: $ 14.43 B` — 게임의 재무 패널과 같은 표기 **[확인: VB-4]**),
  입력란의 금액(백만 달러, 1 ~ 1,000,000)을 **더하기 · 빼기 · 이 값으로**, 빠른 단추 `-$100 B` · `-$10 B` · `$0` · `+$10 B` · `+$100 B` 로 고친다
  **[확인: VB-5 · VB-7]**. 값은 누른 즉시 바뀐다 — 창 바닥에 `마지막으로 쓴 값: 국고 14.43 B -> 24.43 B` 가 나온다. 게임의 설정 창이 뜨지 않고,
  열려 있던 재무 패널의 숫자는 그 패널을 다시 열 때 따라온다 **[확인: VB-6]**. 국고는 음수가 될 수 있다 **[확인: VB-7 · VB-8]**.
  게임 밖에서는 `국고: -` 이고 단추가 꺼져 있다 **[확인: VB-2 · VB-11]**. 쓸 수 없을 때는 단추 대신 까닭 한 줄만 보인다("문제가 생기면").
- **물자 탭**도 내장 치트를 거치지 않는다(3단계 1 (다)). 물자마다 한 줄이다 — 이름, 지금의 재고(게임의 위쪽 자원 표시줄과 같은 표기: `1.8 M` · `129 K`
  **[확인: VC-4]**), 단추 `-1억` · `-100만` · `0` · `+100만` · `+1억` **[확인: VC-5 · VC-7]**. 맨 위의 "모든 물자" 줄은 이번 판에서 쓰는 물자 모두에
  같은 일을 한다 **[확인: VC-8]**. 재고는 0 아래로 내려가지 않는다 **[확인: VC-7]**. 게임 안에서는 이번 판에서 쓰는 물자만 줄로 나오고(독일 · 2030 - 세계에서
  열하나 **[확인: VC-4]**), 게임 밖에서는 이름표의 물자 열하나가 재고 없이(`-`) 나오며 단추가 꺼져 있다 **[확인: VC-2]**. 누른 값은 바로 바뀌고
  창 바닥에 `마지막으로 쓴 값: 석유 779 M -> 879 M`("모든 물자"는 `모든 물자 11개`)가 나온다. 게임 화면의 재고 숫자는 그 패널이나 단추를 누를 때 따라온다 **[확인: VC-5]**.
- **최소 유지**: 돈 탭의 "최소 유지"(백만 달러, 0 ~ 1,000,000)와 물자 탭의 줄마다 맨 오른쪽 칸(수량, 0 ~ 1,000,000,000)의 체크를 켜면,
  값이 그 수준보다 적어질 때 그 수준으로 올린다 — 0.5초마다 본다 **[확인: VD-3 · VD-4 · VD-5]**. 올리기만 한다(값이 그 위로 오르는 것은 막지 않는다).
  **설정 창을 닫아도 돌고 [확인: VD-6], 게임을 껐다 켜도, 새 판을 시작해도 계속된다 [확인: VD-11 · VD-12 — 창을 열지 않은 새 판에 바로 적용됐다].**
  지금 플레이하는 나라의 값만 올린다 — 나라를 바꾸면 그 뒤로는 새 나라의 값을 보고 앞 나라는 건드리지 않는다 **[확인: VE-3]**.
  무엇이 유지되는지는 상태 줄에 늘 보인다. 끄려면 체크를 끈다 — 게임 밖(단추가 꺼져 있을 때)에서도 켜고 끌 수 있다 **[확인: VD-13 은 게임 안에서. 게임 밖은 자동 테스트]**.
  수량은 `Enter` 를 누르거나 다른 곳을 눌러 입력을 마쳐야 쓰인다 — 치는 동안의 값(5, 50, 500 …)은 쓰이지 않고 **[확인: VD-7]**, 치던 채로 창을 닫으면 버려진다 [확인: 자동 테스트].
  유지가 켜진 물자는 이번 판에서 쓰지 않아도 줄이 남는다(재고 칸에 `쓰지 않음`, 단추는 꺼져 있고 그 물자는 유지되지도 않는다 — 켜 둔 것을 끌 수 있게 남는 줄이다) [확인: 자동 테스트].
- **"지식 순위 올리기"(연구 탭) · "세계 시장 여론 최고"(인구·여론 탭) · "관계 최고" · "관계 중립"(외교·영토 탭)도 내장 치트를 거치지 않는다**(3단계 2).
  단추의 이름 · 탭 · 자리는 그대로다. 누르면 값이 바로 바뀌고 창 바닥에 `마지막으로 쓴 값: 기술 수준 110.002 -> 111.002` · `세계 시장 여론 최고` ·
  `관계 최고 — 폴란드 (1106)` 같은 한 줄이 나온다 **[확인: W2 ~ W5]**. 게임의 설정 창이 뜨지 않고 치트 허용 비트가 그대로다 **[확인: W7]**.
  게임 밖에서는 꺼져 있다 **[확인: W1]**. "관계 최고" · "관계 중립"은 지금처럼 목록에서 나라를 고른 뒤 누른다 — 누른 때에 골라 둔 나라와의 관계를 쓴다
  [확인: 자동 테스트]. 쓸 수 없을 때는 그 단추의 자리에 `<단추 이름> — <까닭>` 한 줄만 보인다("문제가 생기면").
- **연구 탭의 "대기열의 연구 즉시 완료" · "기술 수준 N 이하 전부 보유"도 내장 치트를 거치지 않는다**(3단계 3 (가)). 단추의 이름 · 탭 · 자리는 그대로다.
  누르면 바로 바뀌고 창 바닥에 `마지막으로 쓴 값: 기술 1개 · 부대 설계 1개를 완료로 — 대기열` · `기술 45개를 완료로 — 기술 수준 120 이하` 같은 한 줄이 나온다
  **[확인: R1 · R3]**. 게임의 설정 창이 뜨지 않고 치트 허용 비트가 그대로다 **[확인: R4]**. 게임 밖에서는 꺼져 있다 **[확인: R0]**. **전과 달라진 것 넷**:
  - **대기열에 건 부대 설계도 끝난다.** 전에는 기술만 끝났다 — "연구는 지식값은 오르나 일부 연구(군사 연구 등)가 완성되지 않는다"의 원인이 그것이었다.
    끝난 부대는 바로 생산 목록에 나온다 **[확인: R1]**.
  - **다른 기술의 연구 기간을 건드리지 않는다.** 전에는 누르는 순간 대기열에 없는 모든 기술의 연구 기간이 1일이 됐다 — 모든 나라가 함께 쓰는 표라 AI 도 그랬다
    ([07](07-cheats.md)). 이제 그대로다 **[확인: R1 · R3 — 모든 기술의 연구 기간의 합이 한 자리도 바뀌지 않았다]**.
  - **끝낸 것이 화면의 대기열에서 빠진다** **[확인: R1]**. 전에는 끝낸 기술이 대기열에 "대기 중"으로 남았다.
  - **"기술 수준 N 이하"가 선행 기술도 함께 준다**(게임이 연구를 끝낼 때의 규칙이다). 입력란은 1 ~ 255 다(기술 수준은 한 바이트다. 전에는 999 까지 받았다).
  대기열이 비어 있을 때 "대기열의 연구 즉시 완료"를 누르면 창 바닥에 `바꿀 것이 없습니다 — 대기열` 이 나온다 [확인: 자동 테스트].
  게임의 연구 화면은 ToyBox 창을 닫으면 바로 따라와 있었다 **[확인: R1]**. 쓸 수 없을 때는 그 단추의 자리에 `<단추 이름> — <까닭>` 한 줄만 보인다("문제가 생기면").
- **연구 탭의 목록**(3단계 3 (나), 2026-10-10) **[확인: 게임 — R6 ~ R11. 표는 "확인한 것 — 3단계 3 (나)"]**. 위의 단추 셋은 한 줄에 놓이고(설명은 풍선말),
  그 아래에 기술이나 부대 설계의 표가 있다.
  - **거르개**: 기술 / 부대 설계 · 보기 여섯(전체 · 자국 보유 · 자국 미보유(처음 값) · 타국만 보유 · 고른 나라의 보유 · 고른 나라에서 가져올 것) · 분류(기술 여섯, 병과 스물둘) ·
    찾기(이름이나 번호의 일부) · **보유국**(그 나라가 보유한 것만 — 보기와 함께 걸린다. 고르는 목록 안에서 이름 · 번호로 찾는다. 고르면 "고른 나라"도 그 나라가 된다).
    뒤의 두 보기는 "외교·영토" 탭에서 나라를 골라야 고를 수 있다 — 그 나라가 창 위쪽의 "고른 나라" 줄과 표의 마지막 열에 나온다.
  - **표**: 고르는 칸 · 이름 · 분류(병과) · 수준(등장 연도) · 상태(`보유` · `연구 중` · `미보유`) · 보유국(보유한 다른 나라의 이름 — 둘까지 적고 더 있으면 `폴란드, 덴마크 외 3`).
    처음 순서는 수준 · 번호다. **머리 줄을 누르면 그 열로 놓고**(한 번 더 누르면 거꾸로. 보유국은 나라의 수로), **머리 줄의 경계를 끌어 열의 너비를 바꾼다**
    [확인: 게임 — 놓기 · 보유국의 이름 · 보유국으로 거르기. 한글화가 옮긴 부대 이름("시설"의 줄들)도 한글로 보인다].
    기술의 이름은 한글화의 번역 표에서, 부대 설계의 이름은 게임 메모리의 것이다(한글화가 옮긴 이름은 한글, 나머지는 영문). 표는 탭이 보이는 동안 0.5초마다, 그리고 쓴 직후에 새로 읽는다.
  - **단추 넷**: `고른 것 완료` · `고른 것 미완료` · `보이는 것 전부 완료` · `보이는 것 전부 미완료`(한 번 더 눌러야 실행된다). 완료는 선행 기술을 함께 주고,
    기술의 미완료는 그것에 기대는 보유 기술 · 부대 설계도 함께 뺀다(게임의 규칙). "고른 것"은 거르개로 가려진 줄에도 한다 — 그래서 `고른 것 3개(보이지 않는 것 1개)` 로 적는다.
    고른 것은 목록(기술 ↔ 부대 설계)을 바꾸거나 게임에서 나가면 풀린다.
  - **연구 가능으로**(2026-10-16): `고른 것 연구 가능으로` · `보이는 것 전부 연구 가능으로`(한 번 더 누른다). **항목 자체는 보유가 되지 않는다** — 모자란 직접 선행 기술만
    완료로 줘서 그 항목이 게임의 "가능한 연구"에 나오게 하고, 연구 · 개발은 게임에서 기간과 비용을 들여 한다. 부대 탭의 설계도 목록에도 같은 단추가 있다.
    지역만이 막는 항목(`다른 지역 전용`)은 그 지역 코드 비트 하나(새로 여는 항목이 가장 적은 것)를 플레이어 지역의 `+0x40`(CVP 의 `worldavail`)에 더하고 연다 — 같은 코드의 다른 나라 설계도 함께 열리고, 되돌리지 않는다. 바닥 글에 `지역 N개 열림`
    ([설계](superpowers/specs/2026-10-17-toybox-region-unlock-design.md)) [확인: 게임 — 사용자, 2026-10-17].
    선행을 채워도 게임이 보이지 않는 항목은 쓰지 않고 센다 — 플레이어의 지역 코드를 읽지 못했으면 `다른 지역 전용`, 설계가 연구 대상이 아니면 `연구 대상 아님`,
    게임이 연구 목록에서 빼는 설계면 `특수 설계`, 다음 설계를 이미 보유했으면 `이미 개량됨`, 단종 연도가 지났으면 `단종`([설계](superpowers/specs/2026-10-15-toybox-research-unlock-design.md)) [확인: 게임 — 앞 설계가 없는 항목만]. 설계에 업그레이드의 앞 설계(`UGTo` 로 이 설계를 가리키는 설계)가 있는데 하나도 보유하지 않았으면 번호가 가장 낮은 앞 설계 하나를 함께 **등록**한다(그것은 연구 없이 보유가 된다) — 게임은 앞 설계 하나를 보유해야 보이기 때문이다. 바닥 글에 `앞 설계 N개 등록` [확인: 자동 테스트].
  - **상태 열**: `보유`(부대 탭은 `등록`) · `연구 중` · `연구 가능`(선행을 다 가졌다) · `선행 부족` · 열 수 없음의 까닭. 보기에 `연구 가능` · `선행 부족` 이 있다.
  - 쓰는 곳은 위의 두 단추와 같다(플레이어의 비트 · 새 묶음 · 노드의 깃발). 다른 나라의 보유는 읽기만 한다.
- **창의 크기**: 처음 열면 720×600 이다(물자 열하나의 줄이 굴리지 않아도 다 보인다 **[확인: VE-2]**). **이미 써 본 창은 저장된 크기 그대로다** —
  그 전의 500×460 이면 물자 탭의 표가 가로 · 세로로 구른다. 창의 오른쪽 아래 모서리를 끌어 넓히면 그 크기가 저장된다.
- **글쇠 방식**(1 · 2단계 — 게임의 설정 창에 치트를 글쇠로 넣었다)은 지웠다(2026-10-11). ToyBox 는 게임에 글쇠를 넣지 않는다. 그때의 확인(H11 · R6)은 기록으로만 남는다.
- **"외교·영토" 탭**은 나라를 골라 쓴다. 목록에는 이번 판에 실제로 있는 나라만, 한글 이름순으로 보인다(자기 나라는 없다).
  검색란에 한글 · 영문 이름이나 번호의 일부를 넣어 거른다 **[확인: H9]**. 고른 나라는 탭의 내용 위에 `고른 나라: 폴란드 (1106)` 로 보인다 —
  내용을 아래로 내려도 남아 있다 **[확인: H17]**.
  - "동맹 맺기"와 "전쟁 붙이기"는 게임이 **지도에서 고른 나라**를 대상으로 삼는다 — 창을 닫고 지도에서 그 나라의 땅을 한 번 누른 뒤 누른다 **[확인: H7]**.
  - 병합 · 식민지화 · 지도자 제거 · 전쟁 붙이기 · 이 나라로 플레이는 **되돌릴 수 없다.** 한 번 누르면 단추의 글이
    `이 나라로 플레이: 가봉 (414) — 한 번 더 누르면 실행합니다` 처럼 무엇을 어느 나라에 하는지로 바뀌고 **[확인: H17]**, 한 번 더 눌러야
    실행된다 **[확인: H6 ~ H8]**. 그 사이에 다른 나라를 고르거나 창을 닫으면 처음부터 다시 묻는다 [확인: 자동 테스트 · 창을 닫은 경우는 H16].
- 단축키는 "설정" 탭의 "단축키 바꾸기"를 누르고 새 조합을 누르면 바뀐다 **[확인: G7]**. `ESC` 는 취소다 **[확인: R5]**.
- 창이 열려 있는 동안 창 위의 마우스는 게임으로 가지 않는다 **[확인: G5 · G6]**. 입력란에 초점이 있는 동안의 글쇠도 가지 않는다
  **[확인: R3 · R4 — `S`(게임에서는 보급 지도) 한 글쇠로 봤다]**.

모든 줄이 내장 치트를 떠났다 — 국고 · 물자의 치트 여섯(`treasury` · `georgew` · `georgeww` · `products` · `branson` · `bezos`)은 지웠고, 나머지는 묶음마다 직접 쓰기나
게임 자신의 함수로 바꿨다(2026-10-09 ~ 10-11, 아래 "다음 단계"). 그 전에 내장 치트로 본 확인(G · H 번호)은 "확인한 것"에 옛 기록으로 남아 있다.
부대 탭의 "고른 칸" · "고른 부대"는 지도에서 먼저 고른 뒤 누른다.

**넣지 않은 것**

- 모든 지역이나 AI 에 닿는 것 — 요구 2 에 어긋난다: `onedaybuild` `allunit` `gates` `devcheat` `endday` `increaseday` `eventnow` `peace`
  `worldwar` `darren` `democracy` `saddam`. 대상을 모르는 `breakground`.
- 불리해지는 것: `depopulate`(인구가 1) `trumpme`(첫 입력은 -$1 T) `sanction` `wmsanction` `shelovesmenot` `saddamme`.
- 고른 나라와의 관계가 나빠지는 `hate`, 07 에서 반응이 없었던 `liberate` · `revolt`, 번호를 준 경우를 시험하지 않은 `treaty <조약 번호>`.
- GDP 와 장비 수치 — 내장 치트가 없다. 다음 단계.

## 한계

- **"인구 +100만"은 현역 · 예비 인원을 늘리지 않는다**(인구 칸과 그 풀에만 쓴다 — +1,000만을 넣어도 지휘 패널의 현역 166,700 · 예비는 그대로였다 **[확인: 2026-10-22]**). 인원이 모자랄 때는 `인구·여론` 탭의 **예비 인원** 줄을 쓴다.
  예비 인원은 총인구에 들지 않는다 — 예비가 인구를 넘어도 총인구는 늘지 않고, 게임이 자정에 예비를 깎는다 **[확인: 2026-10-22 — 룩셈부르크]**.
- **게임 자체의 문제 — 생산 설계 목록의 "제외 / 표준 / 즐겨찾기" 팝업이 목록을 굴린 양만큼 아래에 뜬다**(모드와 상관없다 — English 에서도 같다 **[확인: 2026-10-23, 1920 × 1080]**).
  팝업의 위끝 ≈ 그 줄의 y − 97 + 굴린 양(px). 많이 굴린 뒤 띄우면 화면 밖에 떠서 보이지 않는데도 열려 있어, 휠이 목록을 굴리지 못하고 줄 강조도 생기지 않는다 — 목록의 제목을 누르면 닫힌다.
  피하는 법: 목록을 맨 위로 굴린 상태에서 띄운다 [추정 — 시험하지 않음]. 1024 × 768 에서는 목록이 짧아 드러나지 않았다.
- **돈 탭이 쓴 뒤에도 열려 있던 게임 패널의 숫자는 스스로 바뀌지 않는다** **[확인: VB-5 · VB-6]** — 일곱 번 누르는 동안 재무 패널은 옛 값이었고,
  다시 열자 새 값이 됐다(아래 직접 실행의 것과 같다).
- **돈 · 물자 탭과 최소 유지만 쓴 판은 게임이 "치트를 쓴 판"으로 알지 못한다.** 치트 허용 비트를 건드리지 않는다 **[확인: VB-5 — 일곱 번 내내 0. 그때 아직 내장 치트로 돌던
  단추를 누르자 1 이 됐다(VB-10). 물자 탭의 `+1억` 열한 번 내내(VC-5), 유지를 켠 직후(VD-3)에도 0 — 물자 탭의 쓰기 70번 동안 로그에 `직접 실행` 이 없었다]**. 사용자가 정한 것이다([설계](superpowers/specs/2026-10-09-toybox-stage3-1-design.md)).
  직접 쓰는 단추 넷(지식 순위 · 세계 시장 여론 · 관계 최고 · 관계 중립)도 같다 **[확인: W7 — 누르는 동안 내내 0]**.
- **"관계 최고" · "관계 중립"은 양쪽에 쓴다.** 내 나라의 지역 객체에 있는 "그 나라" 칸 셋(관계 둘 · 전쟁 명분)과, 그 나라의 지역 객체에 있는 "내 나라" 칸 셋이다 —
  게임의 관계 툴팁의 왼쪽 열과 오른쪽 열이 함께 바뀐다 **[확인: W4 · W5]**. 내장 치트가 하던 것과 같고, 사용자가 정했다(2026-10-10,
  [설계](superpowers/specs/2026-10-10-toybox-stage3-2-design.md)). **ToyBox 가 플레이어가 아닌 나라의 객체에 쓰는 것은 이 칸 셋뿐이다.** 다른 나라와의 관계는 그대로다 **[확인: W6]**.
- **쓴 값을 게임이 언제 다시 고치는지는 보지 않았다.** 시간을 게임 시각으로 2시간 11분 흘리는 동안은 기술 수준 · 여론 · 관계가 한 자리도 바뀌지 않았다 **[확인: W8]**.
  날짜가 넘어갈 때 게임이 관계와 여론을 다시 셈하는지는 보지 않았다 — 내장 치트도 같은 칸에 같은 값을 쓸 뿐이므로 치트를 넣었을 때와 같을 것으로 본다 [추정].
- **"지식 순위 올리기"가 올리는 칸이 무엇인지는 [추정]이다.** 한 번에 그 칸이 정확히 1 오르고(독일 110.0016 → 113.0016), 세 번 뒤 연구 패널의 지식 지수가 6 → 1 이 됐다
  **[확인: W2 — 한 번 뒤의 지식 지수는 보지 않았다]**. 나라마다 다른 값이고(폴란드 94.0, 덴마크 105.0) 게임의 코드에 이 값에 1900 을 더해 쓰는 곳이 있어 "기술 수준"으로 부른다
  ([11](11-game-internals.md)) — 그 숫자가 나오는 게임 화면은 찾지 못했다. 999 에서 멈춘다 [확인: 자동 테스트].
- **한 묶음의 자리를 못 찾으면 그 단추만 꺼진다**(지식 / 여론 / 관계 — 게임이 업데이트됐을 때. 자리에 까닭 한 줄이 보인다). 값 쓰기가 한 번 실패하면 돈 · 물자 · 유지와 함께
  이 넷도 그 실행 내내 꺼진다 [확인: 자동 테스트 — 게임에서는 일어나지 않았다].
- **이번 판에서 없어진 나라와는 관계를 쓰지 않는다**(쓰기 직전에 "이번 판에 실제로 있는 나라"인지 다시 본다) [확인: 자동 테스트]. 병합된 나라의 지역 객체를 게임이 실제로
  어떻게 바꾸는지는 보지 않았다.
- **연구의 두 단추가 쓰는 곳과 부르는 것.** 기술 · 부대 설계의 보유 비트 묶음에서 **플레이어의 비트**, 아무도 보유하지 않던 항목에 거는 새 묶음(128바이트)의 포인터 칸,
  플레이어의 연구 목록 노드의 깃발 두 칸에 쓴다. 기술 표와 부대 설계 표는 모든 나라가 함께 쓰는 표다 — 다른 나라의 비트 · 연구 기간 · 비용에는 쓰지 않는다
  **[확인: R1 · R3 — 폴란드 · 덴마크의 보유와 보정 표가 그대로였다]**. 그리고 **게임의 함수 하나("지역의 효과를 다시 셈")를 플레이어 지역으로 부른다** — 기술의 효과는
  지역마다 미리 계산해 둔 표로 쓰이기 때문이다 **[확인: R2 — 독일의 표만 그 기술들의 효과만큼 바뀌었다]**. 이것이 ToyBox 가 처음 부른 게임의 함수다
  (사용자가 정했다 — [설계](superpowers/specs/2026-10-10-toybox-stage3-3-design.md)의 결정 A). 지금 부르는 함수는 열하나다(외교 · 영토 · 부대 · 화면의 기능 — 저장소의 `CLAUDE.md` · `native/srtoybox/game.h`).
- **그 함수에서 오류가 나면** 창 맨 위에 빨간 글 "효과를 다시 셈하는 중 오류가 났습니다. 저장하지 말고 게임을 다시 시작하십시오."가 뜨고, 그 뒤로는 게임을 다시 띄울 때까지
  ToyBox 가 아무것도 쓰지도 실행하지도 않는다(직접 실행의 오류와 같다) [확인: 자동 테스트 — 게임에서는 일어나지 않았다]. 비트는 그 전에 이미 썼다.
- **이미 내장 치트로 "대기열의 연구 즉시 완료"를 누른 판**(이 빌드 전의 ToyBox, 또는 손으로 넣은 `cheat e=mc2`)은 모든 기술의 연구 기간이 1일인 채다 —
  본래 값이 판에 남아 있지 않아 되돌리지 못한다. 그 판의 대기열에 남은 "끝난" 기술의 노드는 새 단추가 정리한다 [확인: 자동 테스트 — 그런 판을 게임에서 보지는 않았다].
- **아무도 보유하지 않던 기술에는 ToyBox 가 새 묶음을 건다** — 게임과 같은 힙에서 같은 크기로 받는다(게임의 묶음이 그 꼴일 때만. 아니면 그런 항목은 건너뛰고
  `묶음을 만들 수 없는 게임 판입니다 — 보유한 나라가 없는 항목 N개를 건너뜁니다` 를 알린다). 새 묶음 여섯을 건 판이 하루를 진행하고 메인 메뉴로 나올 때까지 멀쩡했다
  **[확인: R3 · R5 · RX]**. **저장 → 불러오기는 보지 않았다.**
- **메모리의 연구 목록에는 끝난 노드가 남는다**(깃발만 켠다 — 게임이 연구를 끝낼 때 하는 것과 같다. 화면의 대기열에는 없다) **[확인: R1 · R5]**.
  게임의 "최근 완료" 칸에는 ToyBox 가 끝낸 것이 나오지 않는다 **[확인: R1]**.
- **연구 묶음은 서명 21개가 모두 맞아야 켜진다**(다른 묶음은 찾을 것마다 셋 가운데 둘). 표의 꼴이 바뀐 빌드에서 엉뚱한 칸에 쓰지 않으려는 것이다 —
  게임이 업데이트되면 다른 기능보다 먼저 꺼질 수 있다. 꺼져도 다른 기능은 그대로다 [확인: 자동 테스트].
- **한 번이라도 연구의 쓰기가 실패하면 연구만이 아니라 값 쓰기 전체가 그 실행 내내 꺼진다**(돈 · 물자 · 최소 유지 · 직접 쓰는 단추 넷도). 연구는 한 번에 수십 ~ 수백 칸을 쓰므로
  다른 기능보다 그럴 기회가 많다 — 쓰기 전에 모든 칸이 쓸 수 있는 쪽인지 먼저 보므로, 실패한다면 한 칸도 쓰기 전이거나(자리의 보호) 쓴 값이 두 번 다 남지 않은 때다
  [확인: 자동 테스트 — 게임에서는 일어나지 않았다].
- **"기술 수준 N 이하"는 지역 마스크가 맞지 않는 기술(다른 지역 전용 [추정])도 준다**(내장 치트와 같다). 한 번 더 누르기가 없다 — 되돌리는 단추(미완료)는 (나)에서 창에 나온다.
- **연구의 두 단추를 본 판은 2030 - 세계 · 독일 하나다.** 날짜는 하루를 넘겨 봤다(R5). DLC 의 판 · 다른 빌드 · 멀티플레이에서는 보지 않았다 — 표의 꼴이 다르면 서명이 맞지 않아 꺼진다.
- **국고는 ±$1,000 T 안에서 음수도 된다** **[확인: VB-7 · VB-8 — −$100 B, 재무 패널에 빨간 글씨]**. 날짜가 넘어갈 때 음수 국고가 어떻게 되는지는 보지 못했다.
- **값 쓰기가 한 번 실패하면 게임을 다시 띄울 때까지 돈 · 물자 탭이 꺼지고 최소 유지도 쉰다**(쓸 수 없는 자리이거나, 쓴 값을 다시 읽어 두 번 다 다를 때).
  시간이 "매우 느림"으로 흐르는 중의 쓰기 열 번은 실패하지 않았다 **[확인: VB-14]**. 게임이 값을 고치는 순간(날짜 넘김)과 겹치는 쓰기는 보지 못했다.
- **최소 유지는 "적어지면 올린다"뿐이다.** 값을 그 수준에 묶어 두지 않고(오르는 것은 막지 않는다), 0.5초 사이에는 그보다 낮을 수 있다.
  게임이 유지 값 아래로 값을 내리는 순간은 보지 못했다 — 26초 동안 석유는 움직이지 않았다(VD-6). 사람이 내린 값을 되올리는 것(VD-5)과
  새 판 · 새 나라의 값을 올리는 것(VD-12 · VE-3)은 봤다.
- **최소 유지를 켜 둔 것을 잊고 새 판을 시작하면 그 판에도 적용된다**(사용자가 고른 동작이다 — 상태 줄을 본다). 유지가 올린 것은 창 바닥의
  `마지막으로 쓴 값` 에 나오지 않고, 로그에도 항목마다 그 실행에서 처음 올린 것만 남는다 — 같은 실행에서 나라를 바꾸거나 값을 내린 뒤의
  되올림은 로그에 없다 **[확인: VD-5 · VD-8]**.
- **`+1억` 이 정확히 1억이 아닐 때가 있다**(늘어난 양이 99,999,997 ~ 100,000,002) **[확인: VC-5]**. 재고 칸이 32비트 실수라 1억대에서는 8 단위로
  반올림된다(약 1,677만부터 낱개 단위가 어긋난다). 한 번에 만들 수 있는 재고는 10억까지다.
- **재고가 0 이어도 게임은 죽지 않았다** **[확인: VC-9 — 물자 열하나를 모두 0 으로 두고 게임 시각으로 55분]**. 날짜가 넘어갈 때는 보지 않았다.
- **물자 이름과 재고 칸의 대응, 열두째 칸은 한 판에서 본 것이다**(2030 - 세계 · 독일과 폴란드) **[확인: VC-5 · VC-6]**. DLC 의 판(1914 · 1936 등)에서는
  보지 않았다 — 그런 판에서 이름과 다른 물자가 오르면 [11](11-game-internals.md)의 표가 그 판에는 맞지 않는 것이다.
- ToyBox 창이 처음 자리(40,60)에 있으면 게임의 속도 목록을 덮는다 — 창을 옮기거나 닫고 고른다 **[확인: VB-14]**. 창을 옮기면 그 자리가 저장된다.
- **오류 가드가 걸리면 상태 줄이 빨간 경고로 바뀌어 유지의 글이 보이지 않는다**(그때 유지는 쉰다. 탭의 체크로 끌 수는 있다) [확인: 코드 — 게임에서는 일어나지 않았다].
- **값을 쓴 뒤, 열려 있던 게임 패널의 숫자는 스스로 바뀌지 않는다** **[확인: H3 · H15 · VB-5 · VB-6]**. 값은 바로 바뀌지만(메모리의 값이 바뀐다) 화면은
  그 패널 안을 누르거나 다시 열 때 따라온다. 일시 정지 중에만 그런 것이 아니다 — 시간이 "매우 느림"으로 흐르는 41초(게임 시간으로 3시간) 동안에도
  재무 패널은 옛 값이었고, 게임의 일시 정지 단추를 누르자 바뀌었다(그 단추여서인지, 게임의 GUI 를 눌러서인지는 가르지 못했다). 날짜가
  넘어갈 때 따라오는지는 보지 못했다. 패널을 다시 열면 된다(예전의 글쇠 방식은 설정 창이 열렸다 닫히며 패널을 다시 그렸지만, 지웠다).
- **ToyBox 의 쓰기와 함수 부르기가 게임의 다른 스레드와 부딪히는지는 모른다.** ToyBox 는 게임이 자기 설정 창의 입력을 처리하는 것과 같은 스레드(창 프로시저)에서
  게임의 함수를 부른다. 날짜를 넘기는 계산이 다른 스레드에서 도는지는 보지 않았다([11](11-game-internals.md)). 시간이 흐르는 중에 눌러 본 것은
  "매우 느림"에서 두 번이고 문제가 없었다(H15). 걱정되면 일시 정지하고 누른다.
- **게임이 업데이트되면 ToyBox 가 게임을 읽지 못할 수 있다.** 서명이 깨지면(찾을 것 하나에서 셋 가운데 둘 이상) 상태 줄에 "읽을 수 없습니다"가 뜨고
  모든 단추가 꺼진다. 값 · 연구 같은 묶음 하나만 못 찾으면 그 묶음의 단추만 꺼진다. 게임이 치트만 없앤 경우에는 ToyBox 의 기능에 영향이 없다 —
  치트 문자열도 치트 코드도 쓰지 않는다(검증 도구의 "옛 찾기"와 `peek` 의 치트 허용 비트만 못 읽는다) [추정: 그런 빌드를 만나지 못했다.
  자동 테스트는 치트 문자열이 없는 가짜 이미지로 본다]. `uv run srkit locate` 가 무엇이 어긋났는지 알려 준다([11](11-game-internals.md)). 다른 빌드에서는 돌려 보지 못했다.
- **게임의 함수를 부르다 오류가 나면** 창 맨 위(상태 줄의 자리)에 빨간 글 "<하던 일> 중 오류가 났습니다. 저장하지 말고 게임을 다시 시작하십시오."가
  뜨고, 그 뒤로는 게임을 다시 띄울 때까지 아무것도 실행하지 않는다 [확인: 자동 테스트 — 가짜 게임에서, 창이 그 글을 맨 위에 그리고 탭의 내용을
  내려도 보이는 것까지. 게임에서는 일어나지 않았고 그 글을 게임 화면에서 본 적은 없다]. 게임의 상태가 어긋났을 수 있으므로 그 판은 저장하지 않는다.
- **나라 목록은 지역의 상태 값으로 거른다**(사람이나 AI 가 맡은 지역만). 그 값의 뜻은 2030 - 세계의 한 판에서 본 분포로 정한 것이다 [추정] —
  실제로 있는 나라가 목록에 없으면 이 가정이 틀린 것이다. 병합한 나라가 목록에서 빠지는지는 보지 못했다.
- **본 판은 둘이다: 2030 - 세계 샌드박스(독일)와 캠페인(독일)** **[확인: H18 — 캠페인에서는 상태 줄과 "국고 +$10 B" 하나]**. 그 밖의 치트는
  샌드박스에서만 봤다. **불러온 저장은 보지 못했다** — 이 PC 에 저장된 게임이 없고, 검증에서는 게임을 저장하지 않는다. 시나리오 판과 다른
  나라로도 보지 않았다 [추정: 같은 구조다]. 그런 판에서 게임을 하고 있는데 상태 줄이 "게임을 진행 중이 아닙니다"로 나오면
  `SRTOYBOX_READ=0` 으로 띄운다("문제가 생기면").
- **불러오는 중(로비에서 "시작"을 누른 직후)에 단추를 누르면 어떻게 되는지 보지 못했다.** 이 PC 에서는 그 구간이 1 ~ 2초이고, 그동안 게임
  창이 메시지에 응답하지 않아 ToyBox 창을 열 수도 없었다(H19). ToyBox 가 "진행 중"으로 보는 값이 된 뒤 게임 화면이 뜨기까지는 0.3 ~ 0.7초였다.
  불러오기가 오래 걸리는 PC 나 판에서는 게임 화면이 뜰 때까지 누르지 않는다.
- **게임의 설정 창 · 게임 메뉴 · 저장 창이 열려 있는 채로 눌러 보지 않았다.** ToyBox 는 글자를 넣지 않으므로 그 창의 칸에 글자가 들어가지는 않는다 [추정].
- **ToyBox 창 위에 마우스를 두면 그 아래 지도의 툴팁이 뜰 수 있다** **[확인: H17 — 검증 도구의 가상 마우스로. 실제 마우스로는 보지 않았다]**.
  누름은 게임에 가지 않는다.
- **한글 검색은 CP949 의 바이트 두 개를 보내 본 것이다** **[확인: H9]**. 실제 입력기로 치는 것은 검증 도구로 볼 수 없다 [추정].
- **치트를 쓴 판에서는 Steam 업적이 주어지지 않는 것으로 보인다** [추정: 코드의 모양만 봤다 — 치트 허용 비트를 검사하는 25곳 가운데 19곳이
  바로 뒤의 업적 호출을 건너뛴다. [11](11-game-internals.md)]. 손으로 치트를 넣어도 같다. 치트 허용은 메뉴로 나오면 꺼진다 **[확인: 실행]**.
- **Steam 오버레이(`Shift+Tab`)가 ToyBox 와 함께 열리는지는 보지 못했다.** 검증 도구가 보낸 `Shift+Tab` 에는 화면이 달라지지 않았다
  (오버레이는 창 메시지가 아니라 실제 키보드를 본다 [추정]). Steam 으로 띄운 게임이 죽지 않고, ToyBox 창이 뜨고, 스스로 끝나는 것까지
  확인했다(아래 "확인한 것").
- **게임이 앞 창일 때(= 실제로 게임을 하는 중에) 단추를 눌러 보지 못했다.** 검증에서는 게임 창이 늘 화면 밖 · 뒤에 있었다. 그때 ToyBox 는
  넣은 뒤 `Ctrl` · `Shift` 를 넣기 전 상태로 되돌린다 **[확인]**. 앞 창일 때는 실제 키보드의 상태를 읽어 맞추는데(`runner_win.cpp`),
  이 갈래는 한 번도 돌지 않았다 [추정]. 검증 도구로 게임을 앞 창에 올리려 했으나 Windows 가 두 방법을 모두 거부했다(2026-10-06).
  치트를 넣은 뒤 `Ctrl` 이나 `Shift` 가 눌린 것처럼 굴면 그 글쇠를 한 번 눌렀다 떼면 풀린다 [추정].
- **Steam 오버레이와 함께 돌 때 다른 오버레이 · 녹화 프로그램이 화면을 못 받을 수 있다** [추정: 해 보지 않았다]. 그때 ToyBox 는
  진짜 `Present` 의 머리를 건너뛰는 길로 간다("구조"). 같은 머리에 점프를 심어 화면을 받는 프로그램(OBS 의 게임 캡처, Discord 오버레이,
  RivaTuner 류)이 Steam 오버레이보다 먼저 걸려 있었다면 그 훅도 함께 건너뛴다. 그런 프로그램에서 게임이 안 보이면 ToyBox 를 끄고
  (`SRTOYBOX=0`) 견주어 본다.
- **게임 창의 크기와 그리는 크기가 다르면** 설정 창이 그 비율로 늘어나(줄어) 보인다. 마우스는 그 비율로 맞춘다
  **[확인: 자동 테스트 — 그리는 크기가 창의 절반일 때]**. 게임에서 그런 상태를 만들어 보지는 않았다(본 것은 둘이 같은 1024x768 창과
  1920x1080 화면 크기 창이다).
- **ToyBox 는 다음 가운데 하나면 끼어들지 않는다**(게임은 그대로, 로그에 까닭) **[확인: 자동 테스트]**: `dxgi.dll` 의 함수 머리가
  ToyBox 가 모르는 명령으로 시작한다(다른 Windows 판) / 다른 훅이 그 머리를 14바이트보다 길게 고쳐 놓았다 / 올라와 있는 `dxgi.dll` 이
  디스크의 파일과 다른 판이다(게임이 떠 있는 동안 Windows 가 파일을 바꿨다).

- **실행 파일의 주소를 적어 두지 않는다.** 화면은 임시 swap chain 에서 가상 함수 표의 주소를 얻어 `Present` 의 칸을 바꾼다. 게임 상태를 읽는
  전역 일곱은 게임이 뜰 때 **치트와 무관한 코드의 서명**으로 찾는다 — 찾을 것마다 서명 셋 가운데 둘 이상이 정확히 한 번 맞고 같은 주소를 내야 한다.
  치트 문자열을 닻으로 쓰는 "옛 찾기"는 DLL 이 게임 안에서 돌리지 않는다 — 검증 도구(`peek` 의 치트 허용 비트 · `srkit locate`)와 테스트의 대조만 부른다.
  찾지 못했거나 읽다가 예외가 나면(읽을 수 없는 쪽) 못 찾은 것으로 친다([11](11-game-internals.md)).
- **게임 읽기.** 자기 프로세스에 대한 `ReadProcessMemory` 로 읽어 낡은 포인터를 만나도 죽지 않는다. 게임 안인데 읽은 값이 서로 맞지 않으면
  (지역 표의 칸 ≠ 플레이어 포인터 등) 구조가 바뀐 것으로 보고 모르는 것으로 친다.
- **값 쓰기.** 게임의 메모리에 쓰는 곳은 플레이어 지역 객체의 국고 1칸 · 재고 12칸 · 기술 수준 1칸 · 세계 시장 여론 3칸 · 관계 표 셋에서 고른 나라의 칸,
  그리고 고른 나라의 지역 객체의 관계 표 셋에서 플레이어의 칸뿐이다(`game.h`). 단추의 요청과 최소 유지가 같은 길로 쓴다 —
  쓰기 직전에 게임을 진행 중인지 · 멀티플레이가 아닌지 · 그 칸이 이번 판에서 쓰는 물자인지 · 쓸 자리가 읽기 · 쓰기 쪽인지를 다시 보고, 쓴 뒤 다시 읽는다.
  관계는 고른 나라가 이번 판에 실제로 있는지(번호 · 인덱스 · 상태)도 다시 본다. 여러 칸을 쓰는 것(여론 · 관계)은 쓰기 전에 모든 칸을 먼저 본다 — 반쪽만 쓰지 않는다.
  요청은 게임 창의 타이머에서 쓴다. **최소 유지**는 그 타이머에서 0.5초마다 켜진 항목에 바닥을 대는 것이다(설정 창이 닫혀 있어도 돈다 —
  타이머는 ToyBox 가 게임 창에 빈 메시지를 한 번 부쳐 건다). ToyBox 가 게임의 함수를 부르는 동안 다시 온 타이머에서는 쓰지 않는다.
- **연구 쓰기**(3단계 3). 쓰는 곳이 더 있다: 기술 · 부대 설계의 보유 비트 묶음에서 플레이어의 비트, 묶음이 없는 항목의 포인터 칸(새 묶음을 걸 때),
  플레이어의 연구 목록 노드의 깃발 두 칸(`game.h`). 요청을 쓸 때마다 표 둘과 플레이어의 연구 목록을 다시 읽고(스냅숏), 규칙(`research`)으로 바꿀 것을 정하고,
  모든 칸이 쓸 수 있는 쪽인지 본 뒤에 쓴다 — 순서는 새 묶음 → 비트 → 노드의 깃발 → 다시 셈. **비트와 깃발은 원자적으로 쓴다**: 보유 묶음의 한 바이트에는
  여덟 나라의 비트가 함께 있어, 읽고 되쓰면 그 순간 게임이 바꾼 다른 나라의 비트를 덮어쓸 수 있다. 새 묶음도 포인터 칸이 아직 비어 있을 때만 건다.
  기술의 보유가 바뀌었으면 끝에 게임의 "효과를 다시 셈"을 **플레이어의 인덱스로 한 번** 부른다(모든 지역으로는 부르지 않는다). 그 호출은 구조적 예외 처리로 감싸고,
  부르는 동안은 다른 함수 호출과 같은 "게임의 함수 안" 깃발을 세운다 — 그 사이에 다시 온 타이머는 쓰지도 부르지도 않는다.
- **게임의 함수 부르기.** ToyBox 가 부르는 게임의 함수(`game.h` 의 머리말)는 창 스레드의 타이머에서, 게임을 진행 중일 때만, 구조적 예외 처리로 감싸 부른다.
  예외가 나면 오류 가드가 걸려 게임을 다시 띄울 때까지 아무것도 부르지도 쓰지도 않는다(`runner_win`).
  **부르는 동안 ToyBox 는 아무 잠금도 쥐지 않는다.** 게임의 함수가 안에서 메시지를 돌리거나 화면을 내보내면 ToyBox 의 타이머 · 입력 ·
  그리기가 같은 스레드에서 다시 불리기 때문이다. 그동안 온 타이머는 쓰지도 부르지도 않는다 — 게임의 함수를 겹쳐 부르지 않는다.
  (1 · 2단계의 직접 실행 — 치트 명령 처리 함수를 부르던 것 — 과 글쇠 방식은 2026-10-11 에 지웠다.)
- **Steam 오버레이와 함께 돌기.** Steam 오버레이는 진짜 `Present` 의 머리에 점프를 심어 두고, 표에서 본 ToyBox 의 함수를 "원래 함수"로
  부른다. ToyBox 가 진짜 함수를 그대로 부르면 그 점프를 타고 오버레이로 되돌아가 서로 맴돈다 — 처음 두 번은 그렇게 게임이 죽었다
  **[확인: 충돌 덤프]**. 그래서 끼어들 때 `dxgi.dll` 파일에서 함수의 원래 첫 명령들을 읽어, 그것을 실행하고 함수의 그 다음 자리로 뛰는
  "깨끗한 진입로"를 만들어 둔다. 되불렸거나, 표의 칸이 바뀌었거나, ToyBox 의 함수 머리에 점프가 심겼으면 그 길로 간다.
  진입로는 "함수의 첫 14바이트 뒤는 파일과 같다"는 가정 위에 있다. 그래서 끼어들 때 그 뒤의 바이트와 DLL 의 머리말(만든 시각 · 크기 ·
  체크섬)을 메모리의 것과 견주고, 다르면 끼어들지 않는다. `Present` 와 `ResizeBuffers` 는 둘 다 될 때만 함께 끼어든다 — 그리기만 하고
  크기 바꾸기를 놓치면 뒷면을 쥔 채 놓지 못한다.
- **실행기의 글쇠와 사용자의 글쇠를 가르는 법.** 실행기가 보내는 메시지에는 스캔 코드가 없고(`lParam` 의 16 ~ 23번 비트가 0) 실제
  키보드의 것에는 있다. 넣는 동안 스캔 코드가 있는 누름과 글자는 게임에 넘기지 않는다(뗌과 `Alt` 조합은 넘긴다).
  `scripts/gamedrive.py` 가 보내는 글쇠에도 스캔 코드가 없어, 검증 도구로는 이 거르기를 지나친다.
- 외부 소스는 Dear ImGui 하나다(`native/third_party/imgui/README.md` 에 버전과 출처. MIT).

| `값 쓰기 실패 (관계 — 폴란드 (1106)) — 값 쓰기를 끕니다` | 그 쓰기가 실패했다(기술 수준 · 세계 시장 여론도 같은 꼴. 몇 칸을 쓴 뒤였으면 `…, 6칸 가운데 N칸을 쓴 뒤`). 게임을 다시 띄울 때까지 값 쓰기 전체가 꺼진다 |
| `연구를 씁니다 (기술 표 +0x… · 부대 설계 표 +0x… · 연구 목록 +0x… · 다시 셈 +0x…)` | 연구의 자리와 게임의 "효과를 다시 셈" 함수를 찾았다. 연구 탭의 두 단추가 동작한다(build `21347933` 에서 `+0x1829620` · `+0x1829610` · `+0x3568C0` · `+0xBDD380`). `SRTOYBOX_WRITE=0` 이면 `연구를 쓰지 않습니다 (SRTOYBOX_WRITE=0. …)` |
| `연구를 쓸 수 없습니다 (<무엇>: 서명 3개 가운데 2개)` | 연구 묶음을 찾지 못했다(게임이 바뀌었다). 연구는 서명 **하나만** 맞지 않아도 쓰지 않는다. 그 두 단추만 꺼지고 자리에 같은 까닭이 보인다. `세계 객체: 지역 표까지의 거리가 맞지 않습니다` · `다시 셈 함수: 찾은 주소가 함수의 시작이 아닙니다` · `… 세계 자료 포인터 의 자리와 겹칩니다` 는 서명이 엉뚱한 것을 읽었다는 뜻이다 |
| `연구 완료 (대기열): 기술 1개 · 부대 설계 1개 · 대기열에서 2개` · `연구 완료 (기술 수준 120 이하): 기술 45개 · 새 묶음 6개` | 연구 탭의 두 단추로 쓴 것. 괄호 안은 무엇을 — `대기열` · `기술 수준 N 이하`. `기술 12개(선행 5개 포함)` 는 고른 것에 딸려 온 선행 기술의 수, `새 묶음` 은 아무도 보유하지 않던 항목에 건 묶음의 수다 |
| `연구 완료 (대기열): 바꿀 것이 없습니다` | 이미 그 상태였다(대기열이 비었다). 한 칸도 쓰지 않았다 |
| `묶음을 만들 수 없는 게임 판입니다 — 보유한 나라가 없는 항목 N개를 건너뜁니다` | 게임의 보유 묶음이 ToyBox 가 아는 꼴(프로세스 힙의 128바이트)이 아니다. 그런 항목만 건너뛰고 나머지는 쓴다 |
| `연구의 표를 읽을 수 없습니다 (<무엇>)` | 그 요청 때 기술 · 부대 설계의 표나 연구 목록을 읽지 못했다(자리 수가 말이 안 된다 · 읽을 수 없는 주소 · 끝나지 않는 목록). 쓰지 않았다. 다음에 누르면 다시 읽는다 |
| `연구 쓰기 실패 (기술 2 의 보유 묶음) — 값 쓰기를 끕니다` | 쓸 수 없는 자리였거나 쓴 값이 남지 않았다(몇 칸을 쓴 뒤였으면 `…, N칸 가운데 M칸을 쓴 뒤`). 게임을 다시 띄울 때까지 값 쓰기 전체가 꺼진다 |
| `효과를 다시 셈하는 중 예외 0x… — ToyBox 를 멈춥니다` | 게임의 "효과를 다시 셈" 함수 안에서 오류가 났다. 창 맨 위에 빨간 경고가 뜬다. 그 판은 저장하지 말고 게임을 다시 시작한다 |
| `게임 상태를 읽지 않습니다 (SRTOYBOX_READ=0) — 단추가 꺼집니다` | 그 환경 변수를 준 채 띄웠다. 모든 단추가 꺼진다 |
| `게임에서 읽은 값이 서로 맞지 않습니다 — 단추가 꺼집니다` | 주소는 찾았지만 구조가 바뀐 것 같다. 위와 같다 |
| `다른 훅과 함께 돕니다 (…)` | 다른 훅을 만나 깨끗한 진입로로 가고 있다(정상) |
| `화면에 끼어들지 못했습니다 (…)` | ToyBox 는 동작하지 않는다. 게임은 그대로다. 괄호 안이 까닭이다 — `원래 함수의 머리를 옮길 수 없습니다`(ToyBox 가 모르는 명령), `다른 훅이 원래 함수의 머리를 길게 고쳐 놓았습니다`, `올라와 있는 DLL 이 디스크의 파일과 다릅니다`(Windows 를 다시 시작하면 풀린다 [추정]), 숫자(Direct3D 장치를 만들지 못했다) |
| `Present1 에는 끼어들지 못했습니다 (…)` | 게임이 그 함수로 화면을 내보낼 때만 창이 보이지 않는다. 나머지는 동작한다 |
| `DirectX 11 장치가 아닙니다` · `ImGui 초기화에 실패했습니다` | 위와 같다 |
| `맑은 고딕(malgun.ttf)이 없습니다` | 창은 뜨지만 한글이 깨진다 |

- 끄려면: `uv run srkit undeploy toybox --apply`. 파일을 둔 채 끄려면 환경 변수 `SRTOYBOX=0` 을 준 채로 게임을 띄운다.
- 값 쓰기(돈 · 물자 탭, 최소 유지, 직접 쓰는 단추 넷, 연구의 두 단추)만 끄려면 환경 변수 `SRTOYBOX_WRITE=0` 을 준 채로 게임을 띄운다. 두 탭에 `값 쓰기를 껐습니다 (SRTOYBOX_WRITE=0)` 한 줄만 보인다 **[확인: VB-13 — 돈 탭]**.
  직접 쓰는 단추 넷의 자리에도 `<단추 이름> — 값 쓰기를 껐습니다 (SRTOYBOX_WRITE=0)` 가 보인다 [확인: 자동 테스트].
  유지가 켜져 있었으면 상태 줄에 `유지 N개 켜짐(값을 쓸 수 없어 쉽니다)` 가 붙는다 [확인: 자동 테스트].
- **최소 유지를 끄고 싶으면 / 켠 적이 없는데 값이 올라가면** — 상태 줄에 무엇이 유지되는지 보인다. 돈 탭의 "최소 유지"와 물자 탭의 맨 오른쪽 칸에서 체크를 끈다
  (게임 밖에서도 된다). 창을 열 수 없거나 두 탭에 까닭 한 줄만 보여 체크가 없으면, 게임을 끄고 `%APPDATA%\SR2030ToyBox\toybox.ini` 의 `keep.` 으로 시작하는 줄을 지운다(없는 줄은 꺼짐이다).
- **돈 · 물자 탭에 단추 대신 까닭 한 줄이 보이면** — 어느 경우에도 내장 치트로 되돌아가지 않는다:
  `이 게임 판에서는 쓸 수 없습니다 (…)` 는 게임이 바뀌어 값의 자리를 찾지 못한 것이다. `uv run srkit locate` 로 어느 서명이 깨졌는지 보고 다시 뽑는다([11](11-game-internals.md)).
  `게임의 값을 읽을 수 없어 쓸 수 없습니다.` 는 그 판의 값(재고 열두 칸, 세계 자료)이 ToyBox 가 아는 모양이 아니라는 뜻이다(보지 못한 구성의 판 — 게임에서 본 적은 없다).
  `값 쓰기가 실패해 껐습니다 …` 는 게임을 다시 시작하면 풀린다. `게임 상태를 읽을 수 있을 때만 씁니다.` 는 상태 줄이 "읽을 수 없습니다"일 때다.
- **"지식 순위 올리기" · "세계 시장 여론 최고" · "관계 최고" · "관계 중립"의 자리에 `<단추 이름> — <까닭>` 한 줄이 보이면** — 까닭의 뜻은 위와 같고,
  어느 경우에도 내장 치트로 되돌아가지 않는다. `이 게임 판에서는 쓸 수 없습니다 (…)` 는 그 단추가 쓰는 자리(지식 / 여론 / 관계의 묶음)의 서명이 깨진 것이다 — 그 단추만 꺼진다.
  `uv run srkit locate` 의 "더 쓰는 값" 절에서 어느 것이 깨졌는지 보고 `uv run srkit sig-mine --offset <자리>` 로 다시 뽑는다([11](11-game-internals.md)).
- **"대기열의 연구 즉시 완료" · "기술 수준 N 이하 전부 보유"의 자리에 `<단추 이름> — <까닭>` 한 줄이 보이면** — 까닭의 뜻은 위와 같고, 어느 경우에도 내장 치트로
  되돌아가지 않는다. `이 게임 판에서는 쓸 수 없습니다 (…)` 는 연구 묶음의 서명이 깨진 것이다 — **하나만 깨져도 꺼진다**(두 단추만. "지식 순위 올리기"는 제 묶음대로다).
  `uv run srkit locate` 의 "연구" 절에서 어느 서명이 깨졌는지 보고 다시 뽑는다 — 함수는 `uv run srkit sig-mine <함수의 RVA> --back 2`, 표와 목록은 꼴의 상수를 든 것으로
  (`--with <상수…>`. 명령의 목록은 [11](11-game-internals.md)).
- **빨간 글 "효과를 다시 셈하는 중 오류가 났습니다. …" 가 떴으면** 그 판을 저장하지 말고 게임을 다시 시작한다(게임의 상태가 어긋났을 수 있다). 로그의
  `효과를 다시 셈하는 중 예외 0x…` 줄이 예외의 코드다. 다시 띄운 뒤에도 그러면 `SRTOYBOX_WRITE=0` 으로 띄워 연구를 포함한 값 쓰기를 끈다.
- **연구 단추를 눌렀는데 창 바닥에 `연구의 표를 읽을 수 없습니다 (…)` 가 나오면** 쓰지 않은 것이다. 한 번 더 눌러 본다 — 계속 그러면 그 판의 표가 ToyBox 가 아는 꼴이 아니다
  (DLC 의 판 · 다른 빌드에서는 보지 않았다).
- **게임을 하고 있는데 단추가 꺼져 있으면**(상태 줄이 "게임을 진행 중이 아닙니다"나 "멀티플레이…"로 잘못 나온다) ToyBox 가 그 판의 상태를 잘못 읽는 것이다.
  `toybox.log` 와 `uv run srkit locate` 의 결과를 남긴다. ToyBox 가 게임을 읽다가 탈이 나면 환경 변수 `SRTOYBOX_READ=0` 을 준 채로 띄워 읽기를 끈다 —
  그때는 모든 단추가 꺼진다(1단계의 글쇠 방식은 지웠다).
- 설정을 처음으로 돌리려면 `toybox.ini` 를 지운다(깨진 파일과 범위 밖의 값은 저절로 기본값이 된다).
- 게임이 죽으면 `%LOCALAPPDATA%\CrashDumps\SupremeRuler2030.exe.<번호>.dmp` 와 빌드할 때 생기는 `build/toybox-obj/srtoybox.map`
  으로 어느 함수인지 찾을 수 있다.

## DLC(Expansion Pass)의 역사 시나리오 — 2026-10-12

DLC 는 1914 · 1917 · 1936 · 1940 ~ 1942 년의 시나리오와 캠페인, 좀비 · 코로나 캠페인이다. 실행 파일은 같고(build 21347933) ToyBox 의 서명도 그대로다.

- **지역의 이름은 판마다 다르다.** 같은 번호가 시대마다 다른 나라다(202 는 현대에 베냉, 역사 시나리오에 다호메이. 1188 은 1914 · 1936 의 독일 — 현대의 표에 없는 번호다).
  번호 532개 가운데 147개가 현대의 이름표에 없고 151개는 표마다 이름이 다르다. 그래서 창의 나라 이름은 **게임이 지금 판에서 쓰는 이름**을 따른다:
  지역 객체의 이름 글을 1초마다 읽어(읽기만) — 이름표의 그 번호가 같은 나라면 이름표의 한글 이름, 다른 나라면 게임의 이름을 "영문 이름 → 한글 이름"의 표
  (모든 지역 번역 테이블에서 빌드할 때 만든다)에서 찾고, 없으면 게임의 이름 그대로. 그 자리를 못 찾은 게임 판에서는 앞처럼 이름표만 쓴다(`#1188`).
  [자동 테스트만 — 역사 시나리오의 화면은 게임에서 보지 않았다]
- **부대 설계 · 기술**: 자료가 본편과 같은 `DEFAULT.UNIT` · `DEFAULT.TTRX` 하나다 — 번호가 같아 설계도 목록 · 연구 목록은 그대로 쓴다(설계의 이름은 게임의 메모리에서 읽는다).
  좀비 시나리오는 `SRZombie.UNIT` · `GCRMZombie.TTRX` 를 쓴다 — 거기서 기술의 이름표가 맞는지는 보지 않았다.

**게임에서 본 것(2026-10-12 — 설치한 뒤)**: 1936 과 1914 의 독일(둘 다 지역 번호 1188)에서 상태 줄이 `플레이 중: 독일 (1188)` 이다(앞에는 `#1188`).
`외교·영토` 탭의 나라 목록은 한글 이름으로 나오고 `#숫자` 꼴이 하나도 없다(`골드코스트 (210)` · `남서아프리카 (403)` · `단치히 (1120)` · `루안다우룬디 (388)` …).
게임이 영어로 쓰는 이름은 그대로 영어다(1936 의 `Sahara (105)`, 1914 의 `Guandongzhou` · `Tsingtao` · `Weihaiwei` · `Zanzibar` — 번역 테이블에 없는 이름).
1936 의 독일에서 `+$10 B` 가 국고를 정확히 100억 올렸고(메모리에서 봤다), 연구 목록(930줄) · 부대 목록(7,490줄) · 배율 탭이 열린다. 로그에 실패 없음.
보지 못한 것: 찾기란의 한글(검증 도구의 한글 입력이 깨져 들어갔다 — 숫자로는 걸러진다), 좀비 시나리오. 창 바닥의 `마지막으로 쓴 값` 은 판을 바꿔도 앞 판의 것이 남는다.
